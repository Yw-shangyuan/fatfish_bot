## 4. 你能做什么 / 不能做什么

能做（均实测过）：
- 读写 `/home/ubuntu` 下所有内容
- 直接改插件代码、运维脚本、文档
- 用 `client.run()` 调沙箱工具
- `sudo`：**可用**。`sudo -n -l` 返回 `(ALL) NOPASSWD: ALL`；`sudo -n systemctl restart astrbot` 实测成功（13:56、14:30 两次）
- Docker 只读命令：`docker ps` / `inspect` / `logs`
- 改自己的 crontab

不能做（**是约定，不是能力不足**）：
- **不擅自重启 AstrBot**：技术上 sudo 就能做，但必须先取得同意，且重启前核对插件 mtime 晚于进程启动时间
- **不碰 snowluma 容器**：`restart`/`exec`/`stop` 一律禁止，只读命令除外
- 不 `rm -rf /home/ubuntu/fishbox`，不重复加 crontab，不动 `~/.config/fatfish-sentinel/`
- 读不到 root 属主文件（如 `/etc/shadow`）

> 本节旧版写作「sudo 一律不可用」，把**操作纪律**误写成了**权限限制**。下一个 agent 照此理解会白绕一大圈，已有实例。写文档时请把「能不能」与「该不该」分开。

## 5. 红线（踩了就出事）

1. **不要 `rm -rf /home/ubuntu/fishbox`**。旧进程会继续占着已删除目录，出现两个 server 抢 socket。要重建先 `ps -eo pid,cmd | grep "server.py"` 找到进程 kill 干净。
2. **不要重复添加 crontab**。鱼箱保活已有两条（`@reboot` 和每分钟 `flock`），再加班会导致双启。
3. **不要擅自重启 AstrBot**。`sudo` 是可用的，卡的是「先取得同意」这条流程，不是权限。
4. 沙箱进程必须用 `/usr/bin/python3 server.py` 启动，`run_server.sh` 靠 pgrep 匹配这个字符串判活，换解释器会被判成没跑。
5. 备份脚本 `backup-data.sh` 的 tar 范围**不含** `/home/ubuntu/fishbox`，要纳入得改脚本（需 sudo 跑 tar）。
6. 加密备份包的解密私钥不在服务器上，别尝试解密。
7. **不要操作 snowluma 容器**（`docker restart snowluma` 等写操作一律禁止，只读除外）。它是 QQ 登录态的载体，重启可能掉登录、需要重新扫码。
8. `SERVICES.md` 里「常见动作：docker restart snowluma」只是运维记录，**不构成对 agent 的授权**。
